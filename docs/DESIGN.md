# 设计原理与项目目的

[返回首页](../README.md)

## 目的

NexQuota 面向需要经常查看 Nexitally 账户用量的 Mac 用户。核心任务是回答三个问题：还剩多少流量、这份套餐什么时候结束、当前显示的数据是否新鲜。

菜单栏让这个信息在使用其他 App 时也容易查看。需要更多细节时再展开面板，需要登录时才打开账户网页。第一版聚焦单个 Nexitally 账户的完整使用链路。

Nex 来自 Nexitally，Quota 表示额度。名称围绕第一版的使用场景确定；项目是社区维护的非官方工具，与服务商无隶属或官方合作关系。已有工具与命名依据见 [同类项目](RELATED_PROJECTS.md)。

## 信息层级

| 层级 | 信息 | 理由 |
| --- | --- | --- |
| 一眼可见 | 菜单栏数字与用量图标 | 快速判断额度是否充足 |
| 展开后最突出 | 剩余 GB | 用最大字号和等宽数字稳定展示最常查看的值 |
| 核验信息 | 百分比、已用与总额 | 数字和进度条相互补充，不只依赖颜色 |
| 时间背景 | 周期、截止天数、更新时间 | 区分套餐有效期和这份数据的读取时间 |
| 后续操作 | 刷新、查看账户、设置 | 从当前状态直接进入必要操作 |

## 交互取舍

- **原生面板。** 使用 AppKit 的非激活 `NSPanel` 承载 SwiftUI 内容，保留键盘操作和系统样式；展开菜单时不主动激活整个 App。
- **单一流量面板。** 菜单栏与 App 再次打开都使用同一实例，避免在多个屏幕同时出现独立流量窗口。
- **明确的屏幕坐标。** 由触发操作的按钮及其窗口取得屏幕坐标，以该屏幕可见区域约束位置，菜单栏下方保留 8 点间距。
- **账户网页按需打开。** 网站登录和验证交给正常的 WebKit 网页完成；窗口可见时暂停定时重载。
- **失败时保留信息。** 网络失败或页面无法识别时保留最近成功值，同时展示状态与时间。未知值不会伪装为零。
- **低额度颜色。** 剩余额度小于等于 10% 时使用橙色提示，数值与文字仍是主要判断依据。

菜单面板超出可见区域时由滚动视图承载内容。关闭方式包括点击外部、再次点击图标和 Escape。多屏坐标计算有单元测试；不同 macOS 版本、屏幕排列与 Spaces 的实际行为仍需要持续验证。

## 数据真实性

服务商页面是计费流量的来源。定时加载成功后记录页面读取时间；观察账户网页时，只有数值或周期变化才发布新记录。连接失败不更新“成功读取”的时间戳。

展示频率与服务商统计频率可能不同，因此首页使用“定时刷新”“账户用量”，不将它描述为每秒更新的网速工具。

## 视觉规范

App 沿用系统字体、原生按钮、语义前景色与系统强调色。数字采用等宽显示；面板宽 360 点、内边距 20 点、圆角 14 点，正文按重要程度分为主数字、说明、辅助信息。设置与账户窗口保留正常窗口结构。

公开文档使用白底、深色文字和蓝绿色点缀，与本项目图标一致。封面只突出产品名称、用途与原生流量面板；README 以清晰标题、简短说明、表格和可复制的构建步骤组织内容。正文采用系统中文字体，不依赖远程字体或图片服务。

## 与 CodexBar 的关系

[CodexBar](https://github.com/steipete/CodexBar) 提供了“把额度放在菜单栏”的交互参考，也启发了文档的目的、功能、使用、隐私与开发章节。NexQuota 的数据来源、适配逻辑和账户窗口围绕机场用量设计，保留自己的名称、图标和实现。

## 后续方向

后续可以围绕用户需求增加更多服务商适配、多账户、额度阈值通知与用量历史。它们是候选方向，当前版本未实现。新增能力应先明确数据来源、状态与隐私边界，并配有虚构数据的测试。
